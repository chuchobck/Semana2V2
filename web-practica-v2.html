Tu primer servidor GraphQL con NestJS

Vas a crear un servidor GraphQL con NestJS (@nestjs/graphql + Apollo), explorarlo con Apollo Sandbox, y conectarlo a una API REST real y pública vía HttpService. Todos los comandos llevan su versión fijada y todas las consultas usan datos que existen de verdad.

2.5 h laboratorio Node 22+ · NestJS 12 · TypeScript 6 Versiones fijadas: sin sorpresas Nivel: principiante
Regla de esta guía: sigue los pasos en orden, sin saltarte ninguno. El botón "Marcar paso completado" solo se activa cuando confirmas la Verificación del paso. Todos los bloques de código tienen botón Copiar: pégalos tal cual, sin corregir tildes ni comillas.
Qué cambió en la v2: esta versión corrige los cuatro errores que hicieron fracasar la v1 — el import sin extensión .js, el identificador productos duplicado, la dependencia @as-integrations/express5 que faltaba, y las consultas que pedían el producto id: 2, que en la API real no existe. Los comandos llevan versión exacta para que el proyecto no se rompa al Actualizar.

Paso 2

Definir el tipo y el resolver

NestJS usa un enfoque code-first con decoradores: @ObjectType() marca una clase como tipo GraphQL, @Field() marca cada campo expuesto, y @Resolver()/@Query() marcan la clase y los métodos que resuelven operaciones.

Crea la carpeta src/productos y dentro los dos archivos siguientes. Los datos de ejemplo usan los mismos ids que la API real (1, 3 y 4), para que lo que veas aquí sea exactamente lo que verás después en el Paso 6.

src/productos/producto.model.ts
import { ObjectType, Field, Int, Float } from '@nestjs/graphql';

@ObjectType()
export class Producto {
  @Field(() => Int)
  id: number;

  @Field()
  nombre: string;

  @Field(() => Float)
  precio: number;
}
src/productos/productos.resolver.ts
import { Resolver, Query, Args, Int } from '@nestjs/graphql';
import { Producto } from './producto.model.js';

@Resolver(() => Producto)
export class ProductosResolver {
  private readonly catalogo: Producto[] = [
    { id: 1, nombre: 'Teclado mecánico', precio: 45.9 },
    { id: 3, nombre: 'Teclado inalámbrico hp', precio: 75.5 },
    { id: 4, nombre: 'MacBook Pro', precio: 3500 },
  ];

  @Query(() => [Producto])
  productos(): Producto[] {
    return this.catalogo;
  }

  @Query(() => Producto, { nullable: true })
  productoPorId(@Args('id', { type: () => Int }) id: number): Producto | undefined {
    return this.catalogo.find((p) => p.id === id);
  }
}

Los dos errores más frecuentes aquí

  • Falta el .js en el import. El proyecto es ESM y el tsconfig.json usa module: nodenext, así que el import debe ser './producto.model.js'. Sin el .js: error TS2307: Cannot find module './producto.model'.
  • El campo y el método se llaman igual. Un atributo productos y un método productos() en la misma clase son el mismo identificador: error TS2300: Duplicate identifier 'productos'. Por eso el atributo se llama catalogo y el método productos().

Pregúntate

¿En qué se parece este ProductosResolver a la clase Query de la teoría (sección 4.2)? Cada método decorado con @Query() es el resolver de ese campo — el mismo "un resolver por campo" que estudiaste, solo declarado explícitamente con un decorador.

Verificación del Paso 2

Paso 3

Registrar el módulo GraphQL en AppModule

Sobrescribe src/app.module.ts completo con este contenido. No agregues líneas sueltas: el archivo que crea nest new importa ObserveModule y src/main.ts usa ObserveInstrument. Si borras esa parte, main.ts deja de compilar con TS2305: has no exported member 'ObserveInstrument'.

src/app.module.ts
import { Module } from '@nestjs/common';
import { createObserveModule } from '@nestjs/observe';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';
import { AppController } from './app.controller.js';
import { AppService } from './app.service.js';
import { ProductosResolver } from './productos/productos.resolver.js';

export const { ObserveModule, ObserveInstrument } = createObserveModule();

@Module({
  imports: [
    ObserveModule.forRoot({
      appKey: 'YOUR_APP_KEY',
      appSecret: 'YOUR_APP_SECRET',
      serviceId: 'nestjs-productos-graphql',
    }),
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: join(process.cwd(), 'schema.gql'),
    }),
  ],
  controllers: [AppController],
  providers: [AppService, ProductosResolver],
})
export class AppModule {}

autoSchemaFile le dice a NestJS que genere el SDL automáticamente a partir de tus decoradores. Fíjate en la ruta: el archivo schema.gql se guarda en la raíz del proyecto, no dentro de src/. Si lo pones en src/, el modo watch detecta el archivo generado y recompila sin parar.

Pregúntate

¿Por qué el resolver va en providers y no en controllers? Porque providers agrupa todo lo que Nest instancia por inyección de dependencias: el resolver necesita resolver los parámetros de sus métodos, igual que un servicio. Los controllers son para endpoints HTTP.

Paso 6

Conectar el resolver a una API REST real

Ahora sobrescribe src/app.module.ts completo. Lo único que cambió respecto al Paso 3 es el import de HttpModule y su registro en imports con HttpModule.register({}):

src/app.module.ts
import { Module } from '@nestjs/common';
import { createObserveModule } from '@nestjs/observe';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { HttpModule } from '@nestjs/axios';
import { join } from 'path';
import { AppController } from './app.controller.js';
import { AppService } from './app.service.js';
import { ProductosResolver } from './productos/productos.resolver.js';

export const { ObserveModule, ObserveInstrument } = createObserveModule();

@Module({
  imports: [
    ObserveModule.forRoot({
      appKey: 'YOUR_APP_KEY',
      appSecret: 'YOUR_APP_SECRET',
      serviceId: 'nestjs-productos-graphql',
    }),
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: join(process.cwd(), 'schema.gql'),
    }),
    HttpModule.register({}),
  ],
  controllers: [AppController],
  providers: [AppService, ProductosResolver],
})
export class AppModule {}

El error que verás si olvidas HttpModule.register({})

La app no compila mal: compila bien y revienta al arrancar con UnknownDependenciesException: Nest can't resolve dependencies of the ProductosResolver (?). Please make sure that the argument HttpService at index [0] is available in the AppModule module. Importar HttpModule no basta — tiene que estar dentro del arreglo imports del decorador @Module.

Y sobrescribe src/productos/productos.resolver.ts completo para que las queries esperen a la API:

src/productos/productos.resolver.ts
import { Resolver, Query, Args, Int } from '@nestjs/graphql';
import { HttpService } from '@nestjs/axios';
import { firstValueFrom } from 'rxjs';
import { Producto } from './producto.model.js';

const API_URL = 'https://nestjs-productos-api.onrender.com/api/v1/productos';

@Resolver(() => Producto)
export class ProductosResolver {
  constructor(private readonly http: HttpService) {}

  @Query(() => [Producto])
  async productos(): Promise<Producto[]> {
    const { data } = await firstValueFrom(this.http.get<Producto[]>(API_URL));
    return data;
  }

  @Query(() => Producto, { nullable: true })
  async productoPorId(
    @Args('id', { type: () => Int }) id: number,
  ): Promise<Producto | undefined> {
    const { data } = await firstValueFrom(this.http.get<Producto>(`${API_URL}/${id}`));
    return data;
  }
}

firstValueFrom (de rxjs) es el puente entre el observable que devuelve Axios y el async/await que entiendes mejor. También podías haber incluido HttpModule en el Paso 1; se separó para que veas por qué cada dependencia se importa en el momento en que la necesitas.

El modo watch recarga solo: espera a que imprima Found 0 errors y repite en Apollo Sandbox las queries del Paso 4. La respuesta debe seguir siendo idéntica, pero ahora viene de internet.

Paso 7 · Reto

Agregar un campo con argumento

Resuelve antes de terminar la sesión

Agrega a ProductosResolver un campo productosBaratos(precioMaximo) que devuelva solo los productos cuyo precio no supere el límite. El decorador @Query() lo expone automáticamente como productosBaratos(precioMaximo: Float!): [Producto!]!. Con los datos reales, 50 devuelve 1 producto y 100 devuelve 2.

Primero añade Float al import de la primera línea:

src/productos/productos.resolver.ts · línea 1
import { Resolver, Query, Args, Int, Float } from '@nestjs/graphql';

Y después, dentro de la clase ProductosResolver, agrega este método antes de la llave de cierre final:

src/productos/productos.resolver.ts · método nuevo
  @Query(() => [Producto])
  async productosBaratos(
    @Args('precioMaximo', { type: () => Float }) precioMaximo: number,
  ): Promise<Producto[]> {
    const { data } = await firstValueFrom(this.http.get<Producto[]>(API_URL));
    return data.filter((p) => p.precio <= precioMaximo);
  }

Nota que el método vuelve a pedir los datos a la API en vez de usar un arreglo local: productosBaratos no existe en una clase vacía, se construye sobre lo que ya sabes hacer. Compruébalo con dos límites distintos:

GraphQL
query {
  productosBaratos(precioMaximo: 50) {
    nombre
    precio
  }
}
GraphQL
query {
  productosBaratos(precioMaximo: 100) {
    nombre
    precio
  }
}
